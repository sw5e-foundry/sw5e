# AGENTS.md

## Cursor Cloud specific instructions

### What this project is
This repo is the **SW5e game system for Foundry Virtual Tabletop** — not a standalone app.
The "application" is loaded and run **inside FoundryVTT**, which is proprietary paid software
and is **not installable in this environment**. Development here means running the build
pipeline that compiles the source (`less/`, `module/`, `sw5e.mjs`, `packs/*.json`, `static/`)
into a loadable Foundry system in `dist/`. To actually play it, a developer points a local
FoundryVTT install's system folder at the generated `dist/` directory.

### Node version (important, non-obvious)
Use **Node 20**. The build tooling in `utils/javascript.mjs` uses the old import-assertion
syntax (`import ... assert { type: "json" }`), which was **removed in Node 22+** and will crash
every `gulp` task (`lint`, `build`, `build:watch`) with `SyntaxError: Unexpected identifier 'assert'`.
The VM's default `/exec-daemon/node` is Node 22, so this matters.

- nvm's default alias is set to Node 20, so **login/interactive shells resolve Node 20 automatically**.
- If a shell reports Node 22 (`node --version`), run `nvm use 20` before any `gulp`/`npm run` command.
- `npm install` itself works on any Node version.

### Commands (all defined in `package.json`; see `CONTRIBUTING.md` for full details)
- `npm run lint` — ESLint via gulp. A clean run reports `0 errors` (there are ~32 pre-existing style **warnings**, which are expected and not failures).
- `npm run build` — `gulp buildAll`: LESS→CSS, bundles JS (`dist/sw5e.mjs` + `dist/vendor.mjs`), compiles `packs/*.json` → NEDB `dist/packs/packs/*.db`, and copies `static/` into `dist/`.
- `npm run build:watch` (or `gulp`) — the dev loop: runs a full build then watches sources and recompiles into `dist/` on change.
- There is **no automated test suite** (no `test` script); validate changes via lint + build, and by loading `dist/` in FoundryVTT when a Foundry runtime is available.

### Gotchas
- `npm install` rewrites one line in `package-lock.json` (`"name": "sw5e"` → the working-dir name) because `package.json` has no `name` field. This churn is harmless; leave it uncommitted.
- Compiled output in `dist/` is git-ignored and regenerated by the build; never commit it.
